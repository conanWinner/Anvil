# Anvil: luồng cốt lõi và kiến trúc

Anvil điều khiển AI coding assistant. **System 3** là domain quản lý Project Lifecycle bên trong Anvil; **Anvil Workflow Runtime** là bộ máy thực thi kỹ thuật dùng chung.

Trọng tâm hiện tại: người dùng đưa một bài toán và bộ dữ liệu vào, chạy nhiều LLM qua 9router, xem code/kết quả riêng, so sánh bằng cùng bộ kiểm tra và nhận gói chạy lại.

## Người dùng cần chuẩn bị gì?

- Blueprint Markdown mô tả bài toán, yêu cầu và điều kiện nghiệm thu.
- Dataset CSV; có thể bổ sung sau Understanding nhưng cần trước khi chạy phần phụ thuộc dữ liệu.
- 2–4 model `router9/<model-id>` đã cấu hình qua [Pi/9router](technical/12-9router-setup.md).
- Prompt chung, requirement IDs và harness Python độc lập để kiểm tra output của từng model.

Dataset Declaration trong blueprint là khai báo dự kiến; Dataset Profile được tạo từ dữ liệu thật. Thiếu dataset không phải lỗi Understanding: Readiness phải chặn ở bước cần dữ liệu.

## Đường đi chính

1. **Tạo dự án:** nhập tên, tải blueprint và dataset; bật So sánh nhiều LLM để cấu hình model và harness.
2. **Hiểu dự án:** chủ động bắt đầu, xem Bản hiểu và trả lời Decision nếu có.
3. **Chuẩn bị:** chấp nhận Bản hiểu; backend chạy Readiness rồi Compile để tạo Execution Plan.
4. **Phê duyệt và chạy:** người dùng duyệt đúng kế hoạch; mỗi LLM có run, code và output riêng, dùng chung Input Snapshot, prompt và harness.
5. **Xác minh:** Verify độc lập chạy lại harness, tạo Evidence theo từng model và requirement.
6. **Bàn giao:** người dùng yêu cầu, kiểm tra gate rồi tải gói chứa code, output, cấu hình, báo cáo và lệnh tái chạy.

Đây là cách nhóm thao tác cho người dùng. Mapping chính thức vẫn là [6 Lifecycle Phase / 10 Lifecycle Activity](lifecycle_activity/README.md); nhiều model chạy bên trong TW-06, không thêm activity.

## Đầu ra và mức hỗ trợ

Đầu ra cốt lõi là code/output riêng của từng LLM, kết quả kiểm tra chung và gói tái chạy. Chạy xong không đồng nghĩa đáp ứng mọi yêu cầu; chỉ Evidence tương ứng mới xác nhận một requirement.

Đã kiểm chứng ngày 16/10/2026: hai LLM thật qua 9router cùng giải bài toán đếm dòng CSV; có code/output riêng, Verify độc lập, tải gói và tái chạy. UI đã xem ở desktop và 390px.

Bản đầu giới hạn Python dùng thư viện chuẩn, CSV vào/JSON ra, chạy tuần tự trong sandbox Linux. Template/readiness còn ràng buộc lịch sử; chưa nghiệm thu bài toán tùy ý, 3–4 model, hủy từng model qua Web hoặc phục hồi giữa tiến trình. Toàn bộ `validate` chưa đạt. Bằng chứng và việc còn lại nằm trong [kế hoạch 11](technical/11-simplification-and-core-flow-plan.md).

## Ranh giới kiến trúc

```text
Anvil Product UI → Backend API → System 3 Control Plane
→ Workflow Compiler → Anvil Workflow Runtime → Storage / Artifact / Evidence
```

| Phần                   | Sở hữu                                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------------------------- |
| System 3 Control Plane | Project, nguồn/phiên bản, Bản hiểu, Decision, Readiness, Compilation, Approval, Evidence và Delivery        |
| Anvil Workflow Runtime | DAG, Workflow Run/Node, retry/timeout, provider session, log, worktree/isolation và lưu artifact dùng chung |
| Provider               | Giao tiếp model; comparison hiện dùng Pi với gateway 9router                                                |

Policy theo bài toán, dataset, target và experiment thuộc `packages/system3`, không đưa vào `packages/workflows`. Chi tiết: [ranh giới và contract](technical/01-system-boundaries-and-contracts.md).

## Các quy tắc cần giữ

- Ghim Source Version và Input Snapshot trước khi chạy; không đọc nguồn “mới nhất” giữa chừng.
- Execution Plan mô tả đúng đầu vào/quyền/model; Approval Manifest ghi đúng nội dung được duyệt. Basis đổi thì phải kiểm tra và duyệt lại.
- Decision là câu hỏi cho người dùng, không phải câu trả lời tự sinh của LLM.
- Artifact là kết quả; Evidence là bằng chứng xác minh. Giữ provenance và lịch sử khi kết quả cũ cần cập nhật.
- Không chạy code LLM ngoài isolation; không tự bàn giao hoặc suy đoán tiến trình đã chết để đổi trạng thái.
- UI mở đầu vào/kết quả inline, trình bày báo cáo dễ đọc; log/hash/JSON nằm trong Chi tiết kỹ thuật. Spec UI: [07](technical/07-system3-lifecycle-ui.md).
