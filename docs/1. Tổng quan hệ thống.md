# Anvil: luồng cốt lõi và kiến trúc

Anvil điều khiển AI coding assistant. **System 3** là domain quản lý Project Lifecycle bên trong Anvil; **Anvil Workflow Runtime** là bộ máy thực thi kỹ thuật dùng chung.

Trọng tâm hiện tại: System 1 research, System 2 chốt các phương án thí nghiệm, **System 3 triển khai nhanh các phương án đó** — agent thi công viết code theo blueprint, agent review kiểm tra, Anvil chạy từng phương án trong sandbox, tự chấm trên tập kiểm tra giữ riêng, gợi ý kèm thống kê và để người dùng chọn. Kế hoạch và tiến độ: [13](technical/13-experiment-execution-plan.md).

## Người dùng cần chuẩn bị gì?

- Blueprint System 2 (Markdown, sáu phần) nêu bài toán, các phương án model (bảng "Model Training - …"), metric chính, ngưỡng và ràng buộc dữ liệu.
- Một hoặc nhiều bảng CSV; có thể bổ sung sau Understanding nhưng cần trước khi chạy.
- Agent thi công và agent review là model `router9/<model-id>` đã cấu hình qua [Pi/9router](technical/12-9router-setup.md); có thể dùng cùng một model.
- Runtime ML đã cài trên máy chạy (`bun run system3:ml-runtime`).

Người dùng không viết harness: Anvil tự chia dữ liệu, giữ nhãn tập kiểm tra và tính metric chính thức.

## Đường đi chính

1. **Tạo dự án:** tải blueprint và dữ liệu (hoặc bộ mẫu Olist), chọn hai agent.
2. **Hiểu dự án:** xem Bản hiểu — phương án, metric, ngưỡng, cách chia — và chấp nhận.
3. **Chuẩn bị và phê duyệt:** Readiness kiểm tra đủ phương án, giao thức đánh giá và runtime; Compile tạo kế hoạch; người dùng phê duyệt đúng kế hoạch đó.
4. **Build (TW-06A):** agent viết `prepare_data.py` và `train_variant.py`, Anvil chạy thử trên mẫu và trả lỗi cho agent sửa; agent review đọc code cùng thống kê dữ liệu. Blueprint mâu thuẫn thì agent dừng và hỏi; review còn lỗi chặn sau các vòng sửa thì hiện cho người dùng.
5. **Chọn cách chạy (TW-06B):** người dùng chọn phương án và số phương án chạy cùng lúc; mỗi phương án chạy offline trong sandbox (2 GB RAM, 2 CPU, ≤ 30 phút). Có thể chạy lại một phần và giữ kết quả cũ cho phần còn lại.
6. **Xác minh (TW-07):** chấm lại độc lập từ gói bất biến; gợi ý theo metric chính và ngưỡng của blueprint.
7. **Bàn giao:** người dùng chọn phương án, tải gói gồm code, dữ liệu, nhãn kiểm tra, kết quả, runtime lock và lệnh tái chạy; manifest ghi phương án đã chọn.

Đây là cách nhóm thao tác cho người dùng. Mapping chính thức vẫn là [6 Lifecycle Phase / 10 Lifecycle Activity](lifecycle_activity/README.md); build và run đều nằm trong TW-06.

## Đầu ra và mức hỗ trợ

Đầu ra cốt lõi là bảng metric do Anvil tính cho từng phương án, gợi ý có lý do và gói tái chạy. Gợi ý không phải quyết định: người dùng chọn.

Đã nghiệm thu qua Web ngày 27/10/2026 với model thật qua 9router trên bộ mẫu Olist (4 phương án, 1.600 dòng kiểm tra). Hiện hỗ trợ phân loại nhị phân trên dữ liệu bảng, CPU, một phương án mỗi lúc trên VPS 4 GB. Chưa có: chạy ở nơi khác rồi tải dự đoán lên, trả lời câu hỏi của agent ngay trên giao diện, trần chi phí token.

Chế độ cũ **so sánh nhiều LLM** (mỗi model tự viết `solution.py`, kiểm tra bằng harness chung — kế hoạch [11](technical/11-simplification-and-core-flow-plan.md)) vẫn chọn được trên form.

## Ranh giới kiến trúc

```text
Anvil Product UI → Backend API → System 3 Control Plane
→ Workflow Compiler → Anvil Workflow Runtime → Storage / Artifact / Evidence
```

| Phần                   | Sở hữu                                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------------------------- |
| System 3 Control Plane | Project, nguồn/phiên bản, Bản hiểu, Decision, Readiness, Compilation, Approval, Evidence và Delivery        |
| Anvil Workflow Runtime | DAG, Workflow Run/Node, retry/timeout, provider session, log, worktree/isolation và lưu artifact dùng chung |
| Provider               | Giao tiếp model; agent thi công/review dùng Pi với gateway 9router                                           |

Policy theo bài toán, dataset, target và experiment thuộc `packages/system3`, không đưa vào `packages/workflows`. Chi tiết: [ranh giới và contract](technical/01-system-boundaries-and-contracts.md).

## Các quy tắc cần giữ

- Ghim Source Version và Input Snapshot trước khi chạy; không đọc nguồn “mới nhất” giữa chừng.
- Execution Plan mô tả đúng đầu vào/quyền/model; Approval Manifest ghi đúng nội dung được duyệt. Basis đổi thì phải kiểm tra và duyệt lại.
- Decision là câu hỏi cho người dùng, không phải câu trả lời tự sinh của LLM.
- Artifact là kết quả; Evidence là bằng chứng xác minh. Giữ provenance và lịch sử khi kết quả cũ cần cập nhật.
- Không chạy code LLM ngoài isolation; không tự bàn giao hoặc suy đoán tiến trình đã chết để đổi trạng thái.
- UI mở đầu vào/kết quả inline, trình bày báo cáo dễ đọc; log/hash/JSON nằm trong Chi tiết kỹ thuật. Spec UI: [07](technical/07-system3-lifecycle-ui.md).
